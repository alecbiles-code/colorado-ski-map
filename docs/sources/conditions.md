## 2. Per-provider findings

### 2.1 CAIC and avalanche.org

#### 2.1.1 Terms text relied on

1. API root, `https://api.avalanche.org/` (tested 00:03 UTC, HTTP 200), full body text: "Avalanche.org API" and "Please contact avalanche.org / American Avalanche Associate for permission". (The typo "Associate" is in the original.)
2. NAC Public API User Guide, `https://github.com/NationalAvalancheCenter/Avalanche.org-Public-API-Docs` README (read 00:07 UTC; repo has no license file): "The data is limited to the danger level on a scale of 1 - 5 as defined in the North American Avalanche Danger Scale. The full avalanche forecast(s) can be accessed through individual avalanche center websites." And: "Avalanche.org collects and distributes this data from 20 independent forecasting operations working under a collective initiative. As a result, it is very important that 3rd party use does not somehow inadvertently change the intent, understanding, or accuracy of the information -- doing so could jeopardize the collective." And: "because avalanche danger changes on a day-to-day basis, danger rating displays must be published and expired accordingly." Display guidance in the same file: black polygon outlines, thick red outline at Extreme, "Polygons display the highest danger rating assigned for that zone during a 24hr period", grey with blue outline for "Avalanche Information Available - No Rating", associated zone name, issue and expiry, center name, and "Link to Forecast or Summary Product (this opens AC forecast page)". The guide documents only `map-layer` and `map-layer/{center}`.
3. CAIC Terms of Use, `https://avalanche.state.co.us/terms-use` (tested 00:04 UTC, HTTP 200): "This website is intended for use by natural persons in obtaining information provided by CAIC. Use of computerized “robots” or “data mining” of the information and images presented here is prohibited." And under Copyright: "Some of the materials made available on this website are the intellectual property of CAIC and are protected by applicable law and may not be reproduced, in whole or in part, without the prior written permission of CAIC."
4. CAIC Release Notes, `https://avalanche.state.co.us/release-notes` (tested 00:04 UTC): "Add ability to fetch historic forecast for point via URL (?date=YYYY-MM-DD). Example: https://avalanche.state.co.us/?lat=39.086&lng=-106.833&date=2023-01-01", "Location Awareness on Mobile: mobile device users can retrieve the forecast for current location", and (1.1.7) "Past forecast URLs: made it easier for users to share past forecasts by making dates and locations stored in URL."

Discrepancy flagged, not resolved here: the NAC guide explicitly contemplates third-party display of the map layer under conditions, while the API root page asks every user to contact avalanche.org for permission, and no license grant exists anywhere. #### 2.1.2 Map layer (`/v2/public/products/map-layer/CAIC`)

Tested 00:03 UTC: HTTP 200, 152,600 bytes, 5.05 s on a cold edge cache (`x-cache: EXPIRED`), 0.67 to 0.73 s warm. Headers: `access-control-allow-origin: *`, `cache-control: max-age=10`, weak ETag. Body is a GeoJSON FeatureCollection of 10 features (`Polygon` and `MultiPolygon`, [lon, lat], 427 to 1,738 vertices each). Properties per feature: `name` (literally "CAIC zone" for every feature, so useless as a label), `center`, `center_id`, `center_link`, `timezone` ("America/Denver", names the center, not the timestamps), `state`, `off_season`, `danger` ("low"), `danger_level` (integer; -1 means no rating per the guide), `travel_advice` (generic text tied to the level), `color`, `stroke`, `font_color`, `fillOpacity`, `fillIncrement`, `link` (always the CAIC homepage, not a zone page), `start_date` and `end_date` (no offset, UTC: "2026-11-05T23:30:00" equals the product's `published_time` "2026-11-05T23:30:00+00:00" and the CAIC page's "Issued Nov 5, 2026, 4:30 PM"), `warning.product` (null). The top-level `start_time` and `end_time` were null.

Gaps: overall danger only (the daily maximum across elevation bands: area 2752 had upper 2, middle 1, lower 1 and the map layer said 2), no elevation bands, no problems, no discussion, no forecast-area name.

Dynamic zones, tested: `GET https://api.avalanche.org/v2/public/avalanche-center/CAIC` returns `"config":{"dynamic_zones":true}` and 260 registered building-block zones (147 active, 113 disabled, no geometry). Each day CAIC groups active building blocks into forecast areas; the map-layer feature `id` is one of the building-block ids and the geometry is the union. Area counts and sizes changed day to day (from the dated product lists): 2026-11-01 eleven areas, sizes 3 to 39 blocks; 11-03 ten areas, 3 to 44; 11-04 eleven, 3 to 39; 11-05 ten, 3 to 41. Feature ids are therefore not stable zone identities; resolve every point against the current geometry. Point-in-polygon on the 00:03 UTC layer: Berthoud Pass (39.7983, -105.7772) and Loveland Pass (39.6638, -105.8794) both fall in feature 2745 (41 blocks: Front Range, Gore Range, Park Range, Elkhead, Medicine Bow, Never Summer, Rabbit Ears, Pikes Peak Massif); Denver falls in none; Silverton in 2660.

#### 2.1.3 Forecast product (`/v2/public/product`)

Tested 00:04 UTC: `?type=forecast&center_id=CAIC&zone_id=2745` returned HTTP 200, 7,184 bytes, `access-control-allow-origin: *`, `cache-control: max-age=2`. Fields: `id` 185706, `published_time`, `expires_time`, `created_at`, `updated_at`, `author`, `product_type` "forecast", `status` "published", `bottom_line` (HTML), `danger` (two objects, `valid_day` "current" and "tomorrow", each with `upper`, `middle`, `lower` integers), `forecast_avalanche_problems` (array), `forecast_zone` (the 41 building blocks with names and GUIDs), `hazard_discussion`, `weather_discussion`, `announcement`, `media` (all null for CAIC), `weather_data` (empty). Area 2752 (product 185711) carried one problem: `name` "Persistent Slab", `likelihood` "possible", `size` ["1.0","2.0"], `location` ["west upper", "northwest upper", "north upper", "northeast upper", "east upper", "southeast upper"], `rank` 1, `problem_description`, `discussion` null.

Verified against CAIC's own rendering (headless Chrome, 00:22 UTC, `?lat=39.05&lng=-106.9`, inside area 2752): "Issued Nov 5, 2026, 4:30 PM", columns "Fri, Nov 6" and "Sat, Nov 7", "Above Treeline 2 - Moderate", "Near Treeline 1 - Low", "Below Treeline 1 - Low", identical bottom line, "Avalanche Problems (1)", "Persistent Slab". So `upper`/`middle`/`lower` map to Above/Near/Below Treeline, and `valid_day` "current" is the local date of `expires_time` (Nov 6), not the issue date (Nov 5). One example; re-check on more products before relying on it.

Reachability of detail: danger by elevation band and day, problem type, aspect and elevation, likelihood, size and the bottom line are reachable. Forecast discussion and travel advice beyond `travel_advice` are not: `hazard_discussion` was null on all 10 products of 2026-11-05, and every CAIC product in four dated lists (42 products) had `product_type` "forecast". CAIC's discussion is a separate `regionaldiscussion` product that lives only on CAIC's AVID path (section 2.1.5).

A building-block id also resolves: `zone_id=2688` (a Front Range block) returned product 185706, the same as 2745. A disabled legacy zone returns success with stale content: `zone_id=2496` ("Steamboat Zone", status disabled) returned HTTP 200 with product 111577, published 2022-06-05 and expired 2022-06-06. HTTP 200 does not mean current; the adapter must check `expires_time`.

Dated list, tested 00:07 UTC: `products?avalanche_center_id=CAIC&date_start=2026-11-05&date_end=2026-11-06` returned 10 summaries (28,696 bytes, 0.43 s; keys include `danger`, `danger_rating`, `bottom_line`, `forecast_zone`, no problems). Without dates the same endpoint returned 142,370,006 bytes (every CAIC product ever); never call it undated.

#### 2.1.4 Official deep link

Tested 00:06 UTC with headless Chrome at a 390 px iPhone viewport: `https://avalanche.state.co.us/?lat=39.7983&lng=-105.7772`. The server returns the same static Astro page for any query (S3 behind CloudFront, `cache-control: public, max-age=0, must-revalidate`); the React island `ForecastMap` reads `lat`, `lng` (parsed as floats) and `date` (`YYYY-MM-DD`) from `location.search`, drops a pin, selects the containing forecast area and opens the forecast panel, then rewrites the URL with `history.replaceState` (lat and lng to 6 decimals). Rendered text: "Low avalanche danger today.", "Issued Nov 5, 2026, 4:30 PM", three elevation bands for Fri Nov 6 and Sat Nov 7, the same bottom line as product 185706, recent photos, tabs "Avalanche Forecast", "Forecast Discussion", "Weather Forecasts". The page needs WebGL2 (ArcGIS JS): with GPU disabled it showed "Unable to display map. WebGL2 support is required." and no forecast panel; with software GL (SwiftShader) it worked. iOS Safari has shipped WebGL2 since Safari 15, but this was not tested on a device. The `/forecasts` path is an index page, not the forecast; the homepage is the forecast map. Not tested: behavior for a point outside every forecast area.

Identified from the site bundle `/_astro/ForecastMap-A2TtHpNv.Cynd1Cr8.js` (read once as a client asset): base `https://avalanche.state.co.us/avid`, paths `products/all/area?productType=avalancheforecast&includeExpired=true`, `products/all?productType=avalancheforecast&includeExpired=true`, the same for `regionaldiscussion` and `specialproduct`, and `datetime=` (21:30 UTC of the chosen date) for history. The page also calls `https://api.weather.gov/points/...` and a CAIC WRF point forecast at `looper.avalanche.state.co.us`. Not used: the Terms prohibit robots and data mining, it is undocumented, and a browser on our origin cannot read it.

#### 2.1.6 Weather app adapter audit (commit 914f4aa)

`loadAvalanche` fetches the map layer from the browser and keeps only features; `avalancheHTML` requires exactly one containing polygon (overlap or none gives a warning pill, never a rating); `bulletinWindow` parses `start_date` and `end_date` as UTC and returns level 0 unless the bulletin is in force. These rules are sound and match the tests above. Two gaps: the link is `p.link`, which is the CAIC homepage, so the location-aware deep link is lost; and the adapter has no notion of elevation bands. Reuse the window logic; replace the link.

#### 2.1.7 Recommendation

1. Permitted now: the deep link from every place, route and GPS point, labeled as the official CAIC forecast. It resolves CAIC's dynamic areas on CAIC's own site, so location awareness needs no API at all.
2. Conditional: the map-layer summary (overall danger, issue and expiry times, area polygon), displayed by the NAC guide's rules and expired at `end_date`. Switch on only after the [ALEC TO CONFIRM] above.
3. Permission needed: the product endpoint (elevation-band danger, problems, bottom line). Missing requirement, exactly: written permission from CAIC (owner of the forecast content, per its Copyright clause) to display its forecast products in this app, and from avalanche.org / the American Avalanche Association (operator of the API, per its root page) to call `/v2/public/product` from a third-party app, including whether an offline copy valid until `expires_time` is allowed. Build the adapter behind `caic.product.enabled = false` so a yes is a config change.
4. Fallback in every failure state (request failed, expired, outside coverage, overlap, off season): no rating, a state label, and the deep link.
5. Consistency rule when detail is enabled: accept a product only if its `published_time` equals the map-layer feature's `start_date` (as UTC) and its `expires_time` is in the future; otherwise show the map-layer summary or the link. A route that crosses several polygons lists each area with its own link.

### 2.2 NWS api.weather.gov

Terms. `https://www.weather.gov/disclaimer` (tested 00:18 UTC): "The information on National Weather Service (NWS) Web pages are in the public domain, unless specifically noted otherwise, and may be used without charge for any lawful purpose so long as you do not: 1) claim it is your own (e.g., by claiming copyright for NWS information -- see below), 2) use it in a manner that implies an endorsement or affiliation with NOAA/NWS, or 3) modify its content and then present it as official government material." API documentation `https://www.weather.gov/documentation/services-web-api` (read 00:10 UTC): "All of the information presented via the API is intended to be open data, free to use for any purpose." "A User Agent is required to identify your application." "The rate limit is not public information, but allows a generous amount for typical use." "the gridX and gridY values (and even the office) for a given coordinate may occasionally change", so "it is necessary to check back to the /points endpoint periodically". "Observations may be delayed up to 20 minutes".

User-Agent in browsers. `fetch` cannot set `User-Agent` in Safari or Chrome; the browser sends its own. Tested: an iPhone Safari UA string got HTTP 200; an empty UA got HTTP 403 "Access Denied" (Akamai HTML, no JSON). The CORS preflight allows `API-Key, Feature-Flags, User-Agent` with `access-control-allow-origin: *`, and `Accept: application/geo+json` is a safelisted header, so a plain browser GET needs no preflight. CAIC's own site calls `/points` from the browser.

`/points` (tested 00:08 UTC). Berthoud Pass 39.7983,-105.7772: `BOU` 36,66, `timeZone` America/Denver, `forecastZone` COZ034, relative to Winter Park 3.8 km. Loveland Pass 39.6638,-105.8794: `BOU` 32,60, COZ034, relative to Keystone 7.1 km. `cache-control: public, max-age=86400`. Six-decimal coordinates return HTTP 301 to the 4-decimal URL (with `access-control-allow-origin: *`); round to 4 decimals client-side to skip the hop and share cache entries.

`forecast` and `forecastHourly` (tested 00:08 UTC, `max-age=3600`, `last-modified` 18:47:48 GMT and 23:59:58 GMT). 12-hour periods and 156 hourly periods. Hourly fields: `startTime`/`endTime` with offset, `temperature` (F by default; `?units=si` returned C and km/h, tested), `probabilityOfPrecipitation` (%), `dewpoint` (C), `relativeHumidity`, `windSpeed` as a string ("7 mph"), `windDirection` as a compass string, `shortForecast`. No gusts and no snowfall amount in either. Envelope: `elevation` (Berthoud cell 3581.1 m, Loveland cell 3474.1 m), `updateTime` 2026-11-05T18:47:50+00:00 (last forecaster edit), `generatedAt` (render time), `validTimes` "2026-11-05T12:00:00+00:00/P7DT13H". The first period of the evening forecast was named "This Afternoon" and spanned 17:00 to 18:00 local; do not assume period names describe full halves of a day.

`forecastGridData` (tested 00:08 UTC, about 222 KB). Values are ISO 8601 interval series (`validTime` "start/PTnH") in SI units. Non-empty at both passes: `temperature` (degC, hourly), `dewpoint`, `maxTemperature`, `minTemperature`, `relativeHumidity`, `apparentTemperature`, `windChill`, `skyCover` (%), `windDirection` (deg), `windSpeed` (km/h), `windGust` (km/h), `weather` (coverage and type objects), `probabilityOfPrecipitation` (% over multi-hour blocks), `quantitativePrecipitation` (mm, 6 h), `iceAccumulation` (mm, 6 h), `snowfallAmount` (mm of snow depth, 6 h blocks, 30 values), `snowLevel` (m, 3 h blocks, 61 values), `transportWindSpeed`, `transportWindDirection`, `mixingHeight`, `probabilityOfThunder`, `heatRisk`. Present but empty: `hazards`, `ceilingHeight`, `visibility`, `potentialOf*` gust fields and the marine and fire indices. Grid elevation is the same per-cell value as the forecast. Ridge-top caution: the 2.5 km cell elevation differs from the named point (Berthoud cell 3581 m against a pass near 3446 m; Loveland cell 3474 m against a pass near 3655 m), so the UI must show the cell elevation.

Alerts (tested 00:08 UTC): `?point=39.7983,-105.7772` returned an empty FeatureCollection, `max-age=5`; `?area=CO` returned 4 alerts with `event`, `headline`, `severity`, `urgency`, `certainty`, `effective`, `onset`, `expires`, `ends`, `areaDesc`, `description`, `instruction`, `affectedZones`.

Failure shapes, tested: unknown point `points/51.5,-0.12` gives HTTP 404 `application/problem+json` `{"title":"Data Unavailable For Requested Point","type":"https://api.weather.gov/problems/InvalidPoint","status":404,"detail":...,"correlationId":...}` with `access-control-allow-origin: *` and `cache-control: private, max-age=86400`; bad gridpoint gives 404 `InvalidGridpoint`. Stale content is not signalled by status: judge it from `updateTime` and from periods whose `endTime` is already past. Not provoked: 5xx and rate-limit responses.

Observations (tested 00:09 UTC). The nearest station to Berthoud Pass is KGNB Granby airport, 35 km away at 2,501 m; next KCCU Copper Mountain at 48 km, 3,666 m. The latest KGNB observation had a valid raw METAR ("09/M06", "17004KT") but `temperature`, `windSpeed`, `windDirection` and `dewpoint` were `null` with `qualityControl: "Z"`. Do not present these as pass conditions; SNOTEL is closer and higher.

Status: usable now from the browser.

### 2.3 Open-Meteo

Terms. `https://open-meteo.com/en/terms` (read 00:10 UTC): "You may only use the free API services for non-commercial purposes." Non-commercial example: "Private or non-profit websites or apps that do not have subscriptions or advertising." Limits: "Less than 10'000 API calls per day, 5'000 per hour and 600 per minute" (the pricing table adds 300,000 per month). "Rate limits are applied by IP addresses and application." "We reserve the right to block applications and IP addresses that misuse our service without prior notice." "You accept to the CC-BY 4.0 licence". Caching and offline storage are not addressed. `https://open-meteo.com/en/licence` (read 00:10 UTC): "API data are offered under Attribution 4.0 International (CC BY 4.0)" and "You must include a link next to any location Open-Meteo data are displayed, for example: <a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>". CC BY 4.0 permits redistribution, so an offline copy with attribution is allowed by the license.

CORS and limits, tested 00:09 UTC: `access-control-allow-origin: *`; response headers `X-RateLimit-Limit: 600.0`, `X-RateLimit-Window: 60`, `X-RateLimit-Remaining`, `X-RateLimit-Cost: 1.0`, exposed to scripts. No cache headers. 0.31 to 0.88 s.

Elevation semantics. Docs: "The elevation used for statistical downscaling. Per default, a 90 meter digital elevation model is used. You can manually set the elevation to correctly match mountain peaks. If &elevation=nan is specified, downscaling will be disabled and the API uses the average grid-cell height." And `cell_selection` default `land` "finds a suitable grid-cell on land with similar elevation". Tested at Berthoud Pass: default returned `elevation` 3449 and grid point 39.80367,-105.76832; `elevation=3446` returned 3446 with identical values at the sampled hour; `elevation=nan` returned 3512 (raw cell) and `temperature_2m` 0.1 C against 0.5 C, about a 6.5 K/km lapse adjustment over 63 m. Snowfall, freezing level and wind were unchanged by the elevation parameter. Treat the downscaling as a temperature lapse-rate adjustment only; label output as "model grid, adjusted to {elevation} m".

Variables, from docs and tests: `snowfall` "Snowfall amount of the preceding hour in centimeters. For the water equivalent in millimeter, divide by 7" (a fixed 7:1 ratio); `snow_depth` instant, m; `freezing_level_height` instant, "Altitude above sea level of the 0°C level"; `wind_gusts_10m` "maximum of the preceding hour", km/h; `precipitation` preceding hour, mm. Model availability at Berthoud (3-day request, tested 00:10 UTC): `best_match` and `gfs_seamless` returned all five variables; `ncep_rrfs_conus` returned all, 48 h; `ncep_nbm_conus` returned no `freezing_level_height` and no `snow_depth`; `ecmwf_ifs025` no `freezing_level_height`; `ncep_hrrr_conus` returned 43 of 72 hours. The docs list "NCEP HRRR U.S. CONUS (Discontinued 2026-11-30)" and "NCEP NAM U.S. CONUS (Discontinued 2026-11-01)", and `best_match` for North America now layers "NOAA RRFS" over the ICON, GFS and IFS backbone. Do not pin HRRR or NAM.

Time. Docs: "Daylight saving time (DST) changes within the requested range are ignored. For DST-aware local times, request timeformat=unixtime and convert using the returned timezone in your application." Use `timeformat=unixtime` (the weather app already does).

Status: usable now (personal, no ads, no subscriptions).

### 2.4 NRCS AWDB REST API

Terms. USDA "Policies and Links", Digital Rights and Copyright (read 00:16 UTC via the mirror `https://usda.azureedge.us/node/6232`, because `https://www.usda.gov/policies-and-links` returned 403 Access Denied to curl and to headless Chrome): "Most information presented on the USDA Web site is considered public domain information. Public domain information may be freely distributed or copied, but use of appropriate byline/photo/image credits is requested. Attribution may be cited as follows: U.S. Department of Agriculture." No AWDB-specific license was found; `nrcs.usda.gov` timed out for automated fetches.

API shape. OpenAPI document `https://wcc.sc.egov.usda.gov/awdbRestApi/v3/api-docs` (tested 00:11 UTC): `/services/v1/stations`, `/data`, `/forecasts`, `/reference-data`. `data` takes `stationTriplets`, `elements`, `duration` (DAILY, HOURLY, ...), `beginDate`/`endDate` (absolute "yyyy-MM-dd HH:mm" or relative `0`, `-n`, tested), `periodRef` (default END), `centralTendencyType`, `returnFlags`, `returnOriginalValues`, `returnSuspectData` (default false).

CORS: `access-control-allow-origin: *`, `access-control-allow-headers: *`, `cache-control: max-age=0, private`.

Station metadata, tested 00:11 UTC. `stations?stationTriplets=*:CO:SNTL` returned 118 active stations, 50,878 bytes, 0.74 s, with `elevation` (ft), `latitude`, `longitude`, `dataTimeZone`, `huc`, `countyName`, `beginDate`. Adding `returnStationElements=true` for all elements returned HTTP 400 "The requested number of station elements exceeds the amount allowed." Filtering to `elements=SNWD,WTEQ,TOBS,PREC,TMAX,TMIN` worked but took 28.3 s for 740,062 bytes, so element discovery belongs in a pipeline snapshot. Element coverage across the 118: SNWD, WTEQ, TOBS, PREC daily and hourly at all 118; TMAX and TMIN daily at 118 but hourly at only 5. Stored units: SNWD in, WTEQ in, PREC in, TOBS degF. Pilot-area stations: 335 Berthoud Summit (11,300 ft), 602 Loveland Basin (11,410 ft), 505 Grizzly Peak (11,110 ft), 970 Jones Pass (10,430 ft), 1186 Fool Creek (11,130 ft), 936 Echo Lake (10,660 ft), 564 Lake Eldora (9,700 ft).

Time zone, tested. Every Colorado SNOTEL station reports `dataTimeZone: -8.0`. Hourly timestamps carry no offset. Cross-correlating 12 days of hourly TOBS (2026-10-25 to 11-06, spanning the 2026-11-01 DST change) with Open-Meteo hourly temperature at the station coordinates, the fit peaked at a fixed UTC-8 for all three stations tested (r = 0.915, 0.917, 0.939 at UTC-8 against 0.883, 0.897, 0.897 at UTC-7). Conclusion: hourly times are fixed UTC-8 (Pacific Standard Time all year, no DST), not Colorado local time. Read the offset from `dataTimeZone`, do not hardcode it. Daily alignment, tested at stations 335 and 602 for SNWD, WTEQ, TOBS and PREC: the daily value dated D equalled the hourly value stamped D+1 00:00 in all 24 comparisons (for example TOBS 22.1 F on 2026-11-02 daily and at "2026-11-03 00:00" hourly). A daily value dated D is therefore the reading at 08:00 UTC on D+1, which is 01:00 MST (02:00 MDT). This refines the weather app's "end-of-day reading" note by the one-hour offset; daily TMAX and TMIN windows follow the same UTC-8 day.

Latency, tested 00:12 UTC: the newest hourly value was stamped "2026-11-05 15:00" (23:00 UTC), about 1 h 12 min old. Today's daily value is absent until the day closes. Observed response times: 0.9 to 1.3 s for small data requests, 28 s for the element metadata; the weather app recorded 4 s to over 100 s on the same request.

Flags and suspect data, tested. With `returnFlags=true` each value carries `qcFlag` and `qaFlag`; observed values were `V` and `S` (QC) and `R` (QA). Meanings from a secondary source (a 2022 PMC table adapted from the NRCS National Engineering Handbook, `https://pmc.ncbi.nlm.nih.gov/articles/PMC9051623/table/undtbl2`): QC `V` valid, `E` edited, `S` suspect; QA `R` raw, `F` flagged, `P` provisional, `A` approved. Not confirmed in AWDB's own docs. Loveland Basin SNWD on 2026-11-04 was -7804 with `qcFlag: "S"`. With the default `returnSuspectData=false` that date was simply missing from the array (no null placeholder), so the adapter must treat an absent date as missing, not as zero. Hourly SNWD at the same station read 2, 7, 2, 2 in over four hours: early-season sensor jitter. Apply plausibility bounds even to unflagged data.

Status: usable now from the browser for data; station element lists via a pipeline snapshot.

### 2.5 SNODAS (NSIDC G02158)

Terms. Landing page `https://nsidc.org/data/g02158/versions/1` (read 00:16 UTC): "As a condition of using these data, you must cite the use of this data set." Citation per the user guide: "National Operational Hydrologic Remote Sensing Center. 2004. Snow Data Assimilation System (SNODAS) Data Products at NSIDC, Version 1. [Indicate subset used]. Boulder, Colorado USA. NSIDC: National Snow and Ice Data Center. https://doi.org/10.7265/N5TB14TC. [Date Accessed]." No other use constraint is stated. The page notes the data set was downgraded to a "Basic" level of service for funding reasons.

Access, tested 00:16 UTC: directory `https://noaadata.apps.nsidc.org/NOAA/G02158/masked/2026/11_Nov/` lists `SNODAS_20261101.tar` to `SNODAS_20261105.tar` (7.5 to 11.0 MB each); unmasked files `SNODAS_unmasked_YYYYMMDD.tar` (16 to 19 MB). No Earthdata login, no key. `SNODAS_20261105.tar`: `Last-Modified: Thu, 05 Nov 2026 14:00:25 GMT`, `Accept-Ranges: bytes`, a Range request returned 206 with `Content-Range`, and no `access-control-allow-origin` header, so a browser on our origin cannot read it.

Format, from user guide 2.1 `https://nsidc.org/sites/default/files/g02158-v001-userguide_2_1.pdf`: flat binary, 16-bit signed big-endian integers with text headers; masked grid 6,935 x 3,351, unmasked 8,192 x 4,096; 30 arc-second cells, geographic WGS84; first value is the NW corner, row-major. Divide by the scale factor: SWE (product 1034) m / 1000, snow depth (1036) m / 1000, both "Snapshot at 06:00 UTC"; melt runoff and sublimation m / 100,000 (24 h totals); solid and liquid precipitation kg/m2 / 10 (24 h totals, 06 to 06 UTC); snowpack average temperature K. NoData -9999. Cautions quoted from the guide: "The SNODAS product is model output and should not be confused with actual observations"; some high-elevation cells have "erroneously high values of SWE"; values at or above 32.767 m saturate at 32,767. Latency: the file for date D (state at 06:00 UTC on D) was posted about 14:00 UTC on D. Processing is the snow lane's job.

Status: usable now, pipeline only.

### 2.7 iOS Safari and Home Screen web app storage

Documented (researched):

1. Quota. WebKit blog "Updates to Storage Policy", Sihui Liu, 10 August 2023, `https://webkit.org/blog/14403/updates-to-storage-policy/`: "For a browser app, the origin quota is up to 60% of the total disk space." "For other apps, the origin quota is up to 15% of the total disk space." Overall quota up to 80% (browser app) and 20% (other apps). A Home Screen web app "has the same origin quota and overall quota as when it is opened in a browser app." Applies from "Safari 17.0, and in WebKit apps for iOS 17, iPadOS 17 and macOS Sonoma."
2. What counts. Same post: the policy covers localStorage, Cache API, IndexedDB, Service Worker and File System data; cookies and HTTP cache are not subject to it. Cache API and IndexedDB therefore share one origin quota; neither is privileged.
3. Eviction. Same post: eviction can happen when the overall quota is exceeded, under storage pressure, or when the site has not been used for some time; "The ordering of origins to be deleted is decided using a least-recently-used policy"; "The last use time is the time of the last user interaction, or the time of the last storage operation"; an origin with an active page or in persistent mode may be excluded.
4. `persist()` and `estimate()`. Same post: "By default, all origins use a best-effort mode"; a site checks with `StorageManager.persisted()` and requests with `StorageManager.persist()`; "WebKit currently grants a request based on heuristics like whether the website is opened as a Home Screen Web App." `StorageManager.estimate()` returns usage and the origin quota, which is "an upper limit, not a guarantee", so `QuotaExceededError` must be handled.
5. Seven-day cap. WebKit blog "Full Third-Party Cookie Blocking and More", John Wilander, 24 March 2020, `https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/`: ITP deletes "all of a website's script-writable storage after seven days of Safari use without user interaction on the site", covering IndexedDB, LocalStorage, media keys, SessionStorage, and "Service Worker registrations and cache". Home Screen apps: "Web applications added to the home screen are not part of Safari and thus have their own counter of days of use. Their days of use will match actual use of the web application which resets the timer. We do not expect the first-party in such a web application to have its website data deleted." So the cap applies in a Safari tab; for a Home Screen app WebKit states it does not expect deletion and would treat it as a bug.
6. Home Screen default. WebKit blog "News from WWDC25: WebKit in Safari 26 beta", 9 June 2025: "By default, every website added to the Home Screen opens as a web app", and users "can turn off “Open as Web App”".
7. Service worker scope. MDN `ServiceWorkerContainer.register()`: "The default scope for a service worker registration is the directory where the service worker script is located"; "A service worker can't have a scope broader than its own location, unless the server specifies a broader maximum scope in a Service-Worker-Allowed header". GitHub Pages cannot set that header, so `/colorado-ski-map/sw.js` registered as `./sw.js` gets scope `/colorado-ski-map/` and cannot touch `/weather/`, as the architecture contract requires. Cache and IndexedDB names are per origin, not per path, so the `skintrack-` prefix is what keeps them apart from the other apps.

Only verifiable on a real device (not tested): whether `persist()` resolves `true` in the installed app and stays true across launches; the `estimate()` quota actually reported; whether a Safari-tab install and the Home Screen app share storage (widely reported as separate containers, not found in WebKit documentation); eviction behavior under storage pressure and after weeks without launch; WebGL2 rendering of the CAIC deep link on iOS.

Consequences for the offline lane: request `persist()` only after an explicit download action and record the result in the package metadata; size packages from `estimate()` with headroom; keep the previous complete package until the new one validates; tell the user in Safari-tab mode that offline data can be cleared after seven days without a visit and that the Home Screen app is the supported offline mode.

## 3. Recommendations for app/config.js

Templates use `{lat}`, `{lon}` in decimal degrees. Timeouts follow the 15 s contract default except where measured otherwise. "Retries" means retries after the first try with backoff (1 s, then 3 s, as in the weather app).

1. `caic.officialLink`: `https://avalanche.state.co.us/?lat={lat}&lng={lon}`, coordinates to 4 decimals, always on. Add `&date=YYYY-MM-DD` only for an explicit past date. Fallback for every CAIC state; label "Official CAIC forecast (opens avalanche.state.co.us)".
2. `caic.mapLayer`: `{ enabled: false, url: 'https://api.avalanche.org/v2/public/products/map-layer/CAIC', timeoutMs: 15000, retries: 1, refreshMs: 600000 }`. Set `enabled: true` only after the [ALEC TO CONFIRM] in 2.1.1. Display only inside `[start_date, end_date)` parsed as UTC; outside it, no color and the label "Expired"; `danger_level` -1 or 0 is "No rating", never Low; exactly one containing polygon or no rating. Offline copies keep `start_date`/`end_date` and render as expired after `end_date`.
3. `caic.product`: `{ enabled: false, url: 'https://api.avalanche.org/v2/public/product?type=forecast&center_id=CAIC&zone_id={zoneId}', timeoutMs: 15000, retries: 1 }`. Permission needed (2.1.7 item 3). When enabled: accept only if `published_time` equals the map-layer `start_date` and `expires_time` is in the future; map `upper`/`middle`/`lower` to Above/Near/Below Treeline; label days by the local date of `expires_time` for "current" and the following date for "tomorrow". Never call the undated `products` list.
4. `caic.avid`: not configured. Rejected (Terms, no CORS).
5. `nws`: `{ enabled: true, points: 'https://api.weather.gov/points/{lat},{lon}', alerts: 'https://api.weather.gov/alerts/active?point={lat},{lon}', timeoutMs: 15000, retries: 2, pointsCacheMs: 86400000, forecastCacheMs: 3600000, alertsCacheMs: 300000, staleUpdateMs: 43200000, observations: false }`. Round to 4 decimals. Follow `forecast`, `forecastHourly` and `forecastGridData` URLs from `/points`; never build grid URLs. Send `Accept: application/geo+json` only (no custom headers, no preflight). Gusts, `snowfallAmount` and `snowLevel` come from `forecastGridData`. `staleUpdateMs` is a judgment knob, not an NWS rule: flag the forecast when `updateTime` is older than it. A 404 problem+json on `/points` means outside NWS coverage, distinct from a network failure.
6. `openMeteo`: `{ enabled: true, url: 'https://api.open-meteo.com/v1/forecast', models: 'best_match', timeformat: 'unixtime', hourly: 'temperature_2m,precipitation,snowfall,snow_depth,freezing_level_height,wind_speed_10m,wind_gusts_10m,wind_direction_10m,cloud_cover,weather_code', forecastDays: 7, timeoutMs: 15000, retries: 2, cacheMs: 1800000, attribution: 'Weather data by Open-Meteo.com', attributionUrl: 'https://open-meteo.com/' }`. Pass `elevation` only when the selected point has a DEM elevation from our own terrain product, and show it; otherwise show the returned `elevation`. Snowfall is a fixed 7:1 model estimate. Do not pin `ncep_hrrr_conus` (discontinued 2026-11-30) or NAM.
7. `snotel`: `{ enabled: true, base: 'https://wcc.sc.egov.usda.gov/awdbRestApi/services/v1/', stationsSnapshot: './data/snow/snotel-stations.json', elements: 'SNWD,WTEQ,TOBS,PREC,TMAX,TMIN', timeoutMs: 30000, retries: 2, cacheMs: 1800000, returnFlags: true, returnSuspectData: true }`. Request suspect data and flags so suspect values are shown as flagged rather than silently absent, and still treat any absent date as missing. Convert hourly times with each station's `dataTimeZone` (fixed UTC-8 for all Colorado SNOTEL), never with America/Denver rules; a daily value dated D is the reading at D+1 08:00 UTC. Plausibility knobs (judgment values, not NRCS constants): reject SNWD < 0 or > 400 in, WTEQ < 0 or > 150 in, TOBS < -60 or > 100 F. Batch all nearby triplets in one request; fetch hourly history only on demand.
8. `snodas`: no browser access. Pipeline source `https://noaadata.apps.nsidc.org/NOAA/G02158/masked/{YYYY}/{MM}_{Mon}/SNODAS_{YYYYMMDD}.tar`, run after 15:00 UTC; the app reads the snow lane's static product and its `*.meta.json` (analysis time 06:00 UTC, citation).
9. `nohrscMapService`: `{ enabled: false, export: 'https://mapservices.weather.noaa.gov/raster/rest/services/snow/NOHRSC_Snow_Analysis/MapServer/export?bbox={bbox-epsg-3857}&bboxSR=3857&imageSR=3857&size=256,256&format=png32&transparent=true&layers=show:0&f=image', timeoutMs: 15000 }`. Optional "latest SNODAS (NOAA service)" layer, off by default, labeled latest-only with unconfirmed units; prefer the pipeline product.
10. `nohrscSnowfall`: pipeline only, `https://www.nohrsc.noaa.gov/snowfall_v2/data/{YYYYMM}/sfav2_CONUS_24h_{YYYYMMDDHH}.nc`; label as an analysis, not a measurement.
11. Storage: request `navigator.storage.persist()` on first offline download, store the boolean in the package metadata, and show it; size packages from `navigator.storage.estimate()`; catch `QuotaExceededError` on every write.
