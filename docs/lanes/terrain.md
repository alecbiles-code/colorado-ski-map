## 2. Decisions

1. Analysis DEM quantized to 0.1 m before slope (exactness of the browser inspector; slope effect under 0.1 degree).
2. Numeric product stores elevation only, on the UTM grid (custom block addressing inside PMTiles), and the browser recomputes Horn. Exact, and 2 to 3 times smaller than storing slope and aspect.
3. Superseded by the contract amendment (section 4.1): aspect is corrected to true north per cell.
4. Regional split: 1x1 degree cells named like 3DEP tiles; each region's display tiles are masked to its cell (west and north edges inclusive) so neighbouring archives never overlap; `regionCellName(lon, lat)` in terrain-math.js routes a point to its cell.

## 5. DNS workaround and a georeferencing fix (2026-11-06T00:50Z onward)

1. Network with the lead's authorization: Python and curl through the lead's DNS-over-HTTPS shim (`work/dnsshim`, 1.1.1.1; TLS still verifies the real hostname). GDAL's `/vsicurl/` cannot use that shim (its libcurl does its own lookups and has no DoH option), so for GDAL reads I ran a throwaway localhost-only CONNECT proxy (`work/terrain/scratch/connect_proxy.py`, allowlisted to prd-tnm.s3.amazonaws.com, tnmaccess.nationalmap.gov and www.usgs.gov, port 443 only, TLS end to end) started with the shim, and set `GDAL_HTTP_PROXY=http://127.0.0.1:18443` for those runs. No system setting changed; the proxy was stopped after use. Neither tool is part of the project.
2. BUG FOUND AND FIXED (00:57Z): `build_analysis.fetch_source` passed unsnapped bounds to `rasterio.merge`, which copies source pixels by nearest neighbour onto a grid starting at those bounds. The pilot mosaic grid was offset by 0.38 pixel east-west and 0.27 pixel north-south from the 3DEP pixel grid, so every pilot DEM value was displaced about 3.0 m east and 2.8 m south of its true position (measured by least squares on the before/after difference: 3.04 m, 2.84 m). Fix: `snap_to_grid` expands the bounds onto source pixel edges (pytest added). `tier1_vintage.release_dem` had the same sub-pixel pattern and now reads whole-pixel windows. The pilot was rebuilt; new versus old DEM differs by MAE 1.13 m, RMSE 1.43 m. All products, checks and comparisons were rerun on the fixed rasters.
3. FOR THE LEAD: the avalanche lane's copies in `work/avalanche/inputs/` (`pilot_dem`, `pilot_dem_buffered`, `pilot_slope`, copied 00:13Z) are the pre-fix rasters (md5 5df4721d... versus the current 65e1bd6d...). They co-register to the grid but their terrain is shifted about 4 m. They should be re-copied from `work/terrain/` before any final avalanche run. I have not contacted that lane.
4. Seam fix (01:23Z): the first pilot versus n40w107 overlap test showed 5 % of DEM cells differing by up to 0.3 m. Causes: GDAL's approximate warp transform (now `tolerance=0`), GDAL widening the bilinear kernel by a per-chunk scale (now `XSCALE=YSCALE=1`, plain 4-point bilinear), and mosaics snapped to each first tile's slightly rounded geotransform (now the exact 1/10800 degree lattice, `pixels_per_degree` in config). After the fix the 201,612-cell overlap is identical for DEM, slope and aspect. The pilot was rebuilt again (final at 01:23Z) and every product, check and comparison was rerun on it. The rows in the methods doc are from this final build. The avalanche lane's copies are stale (see 5.3); current pilot DEM md5: see `md5 work/terrain/pilot_dem_26913_10m.tif`.
