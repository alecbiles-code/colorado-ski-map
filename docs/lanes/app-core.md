## 3. Architecture as built

1. One tile path (`app/map/tiles.js`): `getTile(set, z, x, y)` reads IndexedDB packages first, then the network (PMTiles via the pmtiles library, XYZ via fetch). MapLibre reaches it through the `skt://` protocol: `skt://tile/<set>/{z}/{x}/{y}` and `skt://terrain/{slope|aspect}/{z}/{x}/{y}` (computed). Contours use maplibre-contour's LocalDemManager with a `getTile` hook into the same path (main thread; ponytail note in map.js).
2. Basemap: the lead's 23 archives are one tile set; the first archive whose zoom range and bounds cover the tile wins; none means an empty vector tile.
3. Tier 1 DEM is a config switch (`CONFIG.terrain.provider`): Mapterhorn (Terrarium WebP, 512 px, z13 max) by default, AWS Terrain Tiles as fallback. Offline packages read Mapterhorn tiles from its download archives (planet.pmtiles z0-12, `6-{x}-{y}.pmtiles` z13+) via `getTile(..., {download: true})`.
4. Tier 1 slope/aspect: Horn 3x3 per pixel with the per-row ellipsoidal pixel size (`terrain-math.js`), neighbour tiles for edges. Rendered at the displayed tile zoom (map zoom 12 and up). Inside the Tier 2 pilot outline Tier 1 is masked (scanline over the coverage polygon) and the Tier 2 display tiles draw instead. Inspector: Tier 2 numeric tiles inside the pilot, else Tier 1 at z13; it names the tier and DEM provider.
5. Layer registry (`app/map/layers.js`) with definitions per group in `app/layers/`. Heavy layers are set up on first enable. Status per layer: off, loading, shown, failed (map error events for its sources), not available yet (product missing), zoom in.
6. Service worker: shell cache-first with background refresh (`skintrack-shell-<version>`), site data network-first into `skintrack-data`, never touches Range requests, `.pmtiles`, cross-origin or out-of-scope URLs, caches only status 200, deletes only older `skintrack-shell-*`.
7. `data/manifest.json` is generated by `work/app-core/gen-manifest.mjs <repo>` from every `data/**/*.meta.json` (url inferred from a sibling file when the meta has none). Rerun after products change. Consider moving the script to `tools/`.

## 4. Decisions

1. Dark chrome, light topo map (better in sun). Slope palette is the Tier 2 display palette so tiers match. SAR uses violet (per-winter) and cyan (hotspots) per the snow-obs lane note; modeled terrain pink and blue placeholders until the avalanche lane publishes its legend; incidents black and grey; official danger colours only for CAIC ratings.
2. Contours: feet by default (200/100/40/20 ft by zoom), metres with the units switch (50/20/10 m).
3. Offline size estimates use average tile sizes in `CONFIG.offline.avgTileBytes`. Basemap 6 KB: measured from the lead's archives (w106-s39: 17.6 MB / 3582 tiles = 4.9 KB; co-z11: 9.9 KB). DEM 125 KB: six Mapterhorn 512 px WebP tiles around Berthoud Pass, z11-z13, were 83-145 KB (section 6). Tier 2 numeric 34 KB: 7.57 MB / 224 tiles. The completion result always reports actual stored bytes.
